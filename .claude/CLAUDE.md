# Trust Account Integrity Engine — Claude Code Project Brief

## What this project is

A Python engine that audits NZ law firm trust accounts for compliance with the **Lawyers and Conveyancers Act (Trust Account) Regulations 2008**. It ingests CSV/XLSX exports from practice-management systems (Actionstep, LEAP, etc.) and produces an exception report, PDF, evidence pack, and funds trail.

## Key commands

```bash
# Run the full test suite (545 tests)
python -m pytest tests/ -q

# Run the pipeline on the sample data (23 seeded violations)
python run.py --config trust_domain/config/coastal_law.toml --as-at 2026-06-25

# Start the web UI (upload CSVs in a browser, no CLI needed)
python app.py
# → http://127.0.0.1:5000/

# Run a single rule's tests
python -m pytest tests/test_r03_source_verification.py -v
```

## Rules implemented

| ID | Rule | Severity |
|----|------|----------|
| R01 | Overdrawn client ledger entry | CRITICAL |
| R02 | Dormant balance — no activity > threshold | CRITICAL |
| R03 | Reconciliation break — ledger ≠ bank (+ source fabrication check) | CRITICAL |
| R04 | Bank line with no matching ledger entry | CRITICAL |
| R05 | Unreconciled ledger entry > age threshold | CRITICAL |
| R06 | FIT balance held beyond transfer deadline | CRITICAL |
| R07 | Fee/disbursement entry lacks invoice reference | WARNING |
| R08 | Fee invoice reference not found in invoice register | WARNING |
| R09 | Fee payment exceeds authorised invoice amount | WARNING |
| R10 | Invoice issue date is after the fee payment date | WARNING |
| R12 | Bulk bank deposit not fully allocated to client ledger | WARNING |
| R13 | Trust bank account running balance goes negative | CRITICAL |

## Input datasets

| Dataset | Required | Used by rules |
|---------|----------|--------------|
| `matter_register.csv` | Yes | R02, R06 |
| `client_ledger.csv` | Yes | R01, R05, R07, R08, R09, R10 |
| `trust_bank_statement.csv` | Yes | R03, R04, R12, R13 |
| `reconciliation_summary.csv` | Yes | R03 |
| `invoice_register.csv` | Optional | R08, R09, R10 |
| `allocations.csv` | Optional | R12 |

## Column mapping

If a firm's CSV uses different column names, add a `[column_map]` section to their `.toml` config. See `coastal_law.toml` for examples and `docs/DATA_HANDLING_BOUNDARY.md` for the full internal field list.

## Config TOML fields

```toml
[client]
firm_name = "..."
reviewed_by = "..."
engine_version = "1.0.0"
review_period = "May 2026"

[paths]
input_dir = "../../data/sample"
output_dir = "../../output/coastal_law"

[thresholds]
dormancy_threshold_days = 365   # R02
unreconciled_age_days   = 30    # R05
unmatched_bank_days     = 5     # R04
fit_transfer_days       = 14    # R06
bulk_min_nzd            = 0.0   # R12

[rules]
enabled = ["R01_OVERDRAWN_CLIENT_LEDGER", ...]
```

## Adding a new client

1. Copy `trust_domain/config/coastal_law.toml` → `trust_domain/config/<firm>.toml`
2. Update `firm_name`, `review_period`, `input_dir`, `output_dir`
3. Add column mappings if needed
4. Run: `python run.py --config trust_domain/config/<firm>.toml`

## Important constraints

- `legal/` is git-ignored — never commit or push anything from that folder
- The repo is public on GitHub — no real client data ever goes in `data/` or `output/`
- `data/sample/` contains only synthetic data generated by `trust_domain/synthetic/generator.py`
